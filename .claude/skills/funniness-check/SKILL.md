# 面白さチェック（開発用）

大喜利の回答群を受け取り、スクリーニング用の順位と指摘を返す。

**前提: LLMによる面白さの絶対評価は信頼できない。** だからこのスキルは絶対評価をしない。人間評価で繰り返し確認された「負けパターン」による減点フィルタと、ペアワイズ比較による相対順位だけを出す。最終判定は常に人間。

## 入力

お題と回答群。1セット（5個程度）の順位付け、または複数セット（スキルあり/なし、モデル間など）の比較。

## 手順

### 1. 0.5秒テスト（回答ごと・独立に）

一読で絵が浮かぶか。読解に2段以上かかるなら記録しろ。

### 2. 減点フィルタ

人間評価で繰り返し確認された負けパターン。該当したら理由付きで記録:

- **誇張のみ**: 程度を盛っただけ（「世界一〜」「〜すぎる」型）
- **概念のみ**: 理屈（実は逆、定義ずらし）は通っているが、質感のある物も起きている現象も出てこない
- **穴埋めパロディ**: 有名フレーズの単語をひとつ入れ替えただけで、入れ替えた語が第二の文脈を連れてこない
- **要説明**: 説明されないと伝わらない。元ネタ依存で一読のトリガーがない
- **冗長**: 同じ内容をより短く言える

### 3. ペアワイズ順位付け

フィルタを通った回答同士を総当たりで比較しろ。基準はひとつ:
**「どちらのほうが声を出して笑えるか」**（ニヤリ＜声出し）。
うまさ・賢さ・技巧は基準にするな。

### 4. セット評価

- 切り口の重複（同じ分解軸が2つ以上ないか）
- 温度（全部ニヤリ止まりの小技になっていないか）

## レポート形式

```
## 面白さレポート

お題: [お題]

### 順位（暫定。人間評価が正）
1. 回答X — [一言理由]
2. ...

### 減点フィルタ該当
- 回答Y: [該当パターンと一言]

### セット所見
- 切り口: [分散している / 〜に偏り]
- 温度: [混ざっている / 全部ニヤリ止まり]
```

## 禁止事項

- **絶対スコアを出すな。** 「82点」の類は全て無意味。順位と指摘のみ
- **自分が生成した回答を評価するな。** 生成と評価は必ず別の呼び出しで行う
- **評価のためにこのリポジトリの他のファイルを読むな。** お題と回答だけで判断しろ。`evaluations/` を読んでからの評価は人間順位の丸写しになり、校正に使えなくなる
- 面白くする提案をするな。評価だけしろ（改善は別の作業）

## 校正

このスキルの判定が `evaluations/` の人間評価と食い違う場合、疑うべきはこのスキルの基準であって人間ではない。校正手順は `DEVELOPMENT.md` を参照。
